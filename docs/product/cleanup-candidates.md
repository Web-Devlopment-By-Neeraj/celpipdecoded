# Cleanup candidates

Companion to `docs/product/celpip-ux-audit.md` (CELPIP-UX-00).

**Nothing in this document has been deleted, moved, or renamed.** This is a
list produced by inspection only. Execution belongs to CLEANUP-01, which
must not start before the preconditions in the last section are met.

Audit date: 2026-07-28
Repository state: 109 files in `public/`, 8 migrations, no `middleware.ts`.

---

## How risk is assigned

| Risk | Meaning |
| --- | --- |
| Low | No code references it. Removing it cannot change runtime behaviour. Verify with one grep, then remove. |
| Medium | Referenced somewhere, or a duplicate of something referenced. Requires a code edit in the same commit, plus a visual check. |
| High | Load-bearing. Assume it stays. Listed only so nobody proposes removing it later without reading why. |

### M2. `/favicon.png` vs `/assets/branding/tae-favicon.png`

  `brandingAssets.favicon`.

### M3. `/georgo.png` vs `/assets/branding/georgo-powered-by.png`

### M6. Duplicate asset formats

- `public/assets/optimized/skills/skill-*.webp` (4 files, 106 to 117 KB).
  These are optimized copies of the **landscape 2816x1536 originals with
  the painted checkerboard background**. They are not usable in UI, and
  `asset-registry.ts` correctly points `skillAssets` at the normalized
  512 versions instead. They are dead output.
- `public/assets/optimized/badges/*.webp` (9 files, 113 to 225 KB). Same
  situation. `badgeAssets` points at the normalized set.
- **Action:** these 13 files are genuine dead weight, roughly 1.8 MB. But
  they are **regenerated by `npm run assets:optimize` on every run**, so
  deleting them without changing `scripts/audit-and-optimize-assets.mjs`

  the `badges` and `skills` categories to the optimize script, or accept

- The 44 normalized PNG twins are **not** in this category. They are the
  deliberate non-WebP fallback registered as `skillAssetsPng` and

All eight files in `supabase/migrations/`. Already applied to hosted

### H7. Asset sources and scripts

- All 9 badge PNGs in `public/assets/badges/`.
- All 4 skill PNGs in `public/assets/skills/`.

- `scripts/normalize-badge-icon-assets.mjs`

- `src/features/assets/asset-registry.ts`
- `src/features/assets/badge-asset-map.ts`
- `src/features/assets/module-asset-map.ts`

These currently have zero importers. **That makes them look like dead
code. They are not.** They are the interface CELPIP-UX-03 is meant to
consume. Removing them because grep shows no callers would destroy two
completed tickets of work. This is the single most likely wrong deletion
in this repository, which is why it is flagged at high risk.

## When cleanup should happen

**CLEANUP-01 runs last, after CELPIP-UX-03.** It must not be pulled
forward.

### Preconditions, all four required

1. **This audit is complete.** Satisfied by CELPIP-UX-00.
2. **The design-system foundation is decided.** CELPIP-UX-01 must have
   shipped, so the set of components and tokens the product keeps is
   settled. Removing a component before then risks deleting something the
   new system was going to reuse.
3. **Asset registry usage is confirmed.** At least one real screen must
   import from `@/features/assets/asset-registry`. Until then, every
   asset in the repository looks unused to grep, and the registry itself
   looks like dead code. Cleaning up in that state is guesswork.
4. **The dashboard redesign has started using optimized assets.**
   CELPIP-UX-03 is what proves which optimized paths the UI actually
   consumes. Once the dashboard renders `dashboardAssets`,
   `emptyStateAssets`, `getModuleAsset()`, and `getBadgeArtwork()`, the
   remaining unreferenced files are genuinely unreferenced.

### Why not earlier

Running cleanup before those four conditions produces exactly the wrong
answer. Today a naive unused-file scan would flag: the entire
`public/assets/optimized/` tree, the entire `public/assets/normalized/`
tree, all three files in `src/features/assets/`, and every source PNG. All
109 asset files except `/favicon.png` and five landing JPGs. That is two
completed tickets of work deleted on the strength of a grep.

### Why not later

Every ticket after CELPIP-UX-03 adds files. Cleanup gets harder, and the
repository ships to production carrying roughly 118 MB of source imagery
in `public/`, all of which Vercel deploys and serves whether or not any
page references it.

### Suggested CLEANUP-01 scope

In order:

1. Delete `public/canada-city-hero.jpg` (L1).
2. Remove the empty `public/reference/` directory; add `.gitkeep` to the
   three intentional empty asset directories (L2).
3. Resolve the favicon duplicate (M2).
4. Repoint `Footer.tsx` at the WebP and remove `/georgo.png` (M3).
5. Move the root landing photos under `public/assets/photos/` **after**
   their references already point at the registry (M1).
6. Decide the optimize-script skip rule for the badges and skills
   categories, then remove the 13 dead optimized files (M6).
7. Decide whether `_reference/canva-design/desktop.png` stays (L3).
8. Re-run `npm run assets:audit` and commit the regenerated inventory.
9. Run `npm run lint` and `npm run build`.
10. Walk every route and confirm no broken image.

Not in scope for CLEANUP-01: anything in the high-risk section, any logo
replacement, and any change to the two asset scripts beyond the single
skip rule in item 6.
