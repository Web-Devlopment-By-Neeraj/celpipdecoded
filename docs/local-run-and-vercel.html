CELPIP Decoded

How to get every environment variable this repo defines, run the app on your machine, and deploy it on Vercel. 13 October 2026. Secrets stay in .env.local and in the Vercel dashboard. Do not put real keys in git or in this PDF.

Existing Supabase project. The app is already pointed at project ewykjltuiipmyrybetbk, URL https://ewykjltuiipmyrybetbk.supabase.co. Use that project. Create a new one only if you intend to start over.

2. Get each value

Supabase URL and keys

  1. Open https://supabase.com/dashboard/project/ewykjltuiipmyrybetbk/settings/api.
  2. If that page has moved, open the project, then Project Settings, then API or API Keys.
  3. Copy Project URL into NEXT_PUBLIC_SUPABASE_URL.
  4. Copy the anon / public JWT into NEXT_PUBLIC_SUPABASE_ANON_KEY. It is a long token starting with eyJ and its payload role is anon.
  5. Reveal the service_role secret and copy it into SUPABASE_SERVICE_ROLE_KEY. It also starts with eyJ, and its role is service_role.

Auth redirects

These are dashboard settings, not environment variables. Sign-in emails fail until they are saved.

  1. Open https://supabase.com/dashboard/project/ewykjltuiipmyrybetbk/auth/url-configuration.
  2. Or: project, Authentication, URL Configuration.
  3. Site URL for local work: http://localhost:3000.
  4. Redirect URLs: http://localhost:3000/auth/callback.
  5. After Vercel gives you a domain, add https://<that-domain>/auth/callback and set Site URL to the live domain.

Database password and connection string

  1. Project, Project Settings, Database.
  2. The password was chosen when the project was created. If it is lost, use Reset database password on that page. Resetting it changes the password for every client that uses it.
  3. Under Connection string, choose URI and Direct connection. The host uses port 5432. That string is SUPABASE_DB_URL.
  4. Do not use the transaction pooler (port 6543) for migrations.

Supabase access token

  1. Open https://supabase.com/dashboard/account/tokens.
  2. Generate a token. That value is SUPABASE_ACCESS_TOKEN.
  3. Project ref is the subdomain: ewykjltuiipmyrybetbk.

OpenAI

  1. Open https://platform.openai.com/api-keys.
  2. Create a secret key. Paste it into OPENAI_API_KEY. The key is shown once.
  3. Set the three model names to the defaults in section 1. Change a model name only when you want a different model.

If a key was pasted into chat, revoke it on that page and create a new one before you deploy.

Stripe

  1. Open https://dashboard.stripe.com and turn Test mode on.
  2. Developers, API keys.
  3. Publishable key → NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY.
  4. Secret key → STRIPE_SECRET_KEY.
  5. Create the webhook after the Vercel domain exists. Developers, Webhooks, Add endpoint. URL: https://<your-domain>/api/webhooks/payments.
  6. Open the endpoint and copy the signing secret (whsec_…) into STRIPE_WEBHOOK_SECRET.

Cal.com

  1. API key: https://app.cal.com/settings/developer/api-keys → CAL_API_KEY.
  2. Webhook secret, after the site URL exists: https://app.cal.com/settings/developer/webhooks → CAL_WEBHOOK_SECRET.

3. Run the project locally

  1. Install Node.js 20.19 or newer. This repo’s .nvmrc is 20. Node 18 cannot load the test runner. In this folder run nvm use.
  2. Install dependencies and create the env file:
cd /Users/novostack/projects/celpipdecoded
nvm use
npm ci
cp .env.example .env.local
  1. Open .env.local and paste the values from section 2. The minimum that lets sign-in and pages load is the two public Supabase values, the service role key, NEXT_PUBLIC_APP_URL=http://localhost:3000, and ADMIN_EMAILS.
  2. Save the Auth redirect URLs from section 2 before you test sign-up email.
  3. Start the app:
npm run dev
  1. Open http://localhost:3000. After any edit to .env.local, stop the server and run npm run dev again. Next.js reads that file at startup.
  2. Optional checks:
npm run lint
npm run typecheck
npm test

The pre-commit hook refuses commits on main or master, then runs lint, typecheck, and tests. Work on a feature branch.

Speaking and writing scores need OPENAI_API_KEY. Checkout needs the Stripe secret. The daily job needs CRON_SECRET, and that job only runs on Vercel.

Apply the database

Auth and saved attempts need the SQL in supabase/migrations. The deploy script applies those migrations only from a clean main that matches origin/main. From that checkout:

export SUPABASE_DB_URL='postgresql://...'   # direct URI, port 5432
bash scripts/deploy.sh production --migrate-only

Or export SUPABASE_ACCESS_TOKEN, SUPABASE_PROJECT_REF=ewykjltuiipmyrybetbk, and SUPABASE_DB_PASSWORD instead of the URI. After the migration that creates the instructional-videos bucket, upload the five local mp4 files with npm run videos:upload.

4. Deploy on Vercel

One owner can deploy on the Hobby plan. A Pro plan is only required when several people must be members of the Vercel team.

The GitHub production workflow deploys main after a pull request merge. The branch that currently holds this work is feature/phase2-neeraj. For a first deploy of that branch, set it as the production branch in the Vercel import screen, or deploy it as a preview and switch production to main after the pull request is merged.

Create the project

  1. Sign in at https://vercel.com with the account that will own the site.
  2. Add New, Project, and import the GitHub repository. The remote used by this repo is Web-Devlopment-By-Neeraj/celpipdecoded.
  3. Framework preset: Next.js. Build command: npm run build. Leave the output directory on the Next.js default.
  4. Before Deploy, open Environment Variables.
  5. Add every name from the first two tables in section 1. Enable Production, Preview, and Development for each.
  6. Use new CRON_SECRET and MEDIA_SIGNING_SECRET values. Set NEXT_PUBLIC_SHOW_EXAM_ANSWER_KEY to false.
  7. If the production URL is not known yet, set NEXT_PUBLIC_APP_URL to a placeholder, deploy, then replace it with the real https:// URL and redeploy.
  8. Choose the production branch (feature/phase2-neeraj for this work, or main after merge) and click Deploy.

The project page shows a URL such as https://<project>.vercel.app. Later pushes to the production branch build again on their own.

Finish the live site

  1. Set NEXT_PUBLIC_APP_URL in Vercel to that exact URL for Production and Preview, then redeploy.
  2. Add https://<that-domain>/auth/callback in Supabase URL Configuration.
  3. Create the Stripe webhook at https://<that-domain>/api/webhooks/payments, paste STRIPE_WEBHOOK_SECRET, and redeploy.
  4. Confirm the cron in vercel.json is attached. It calls POST /api/cron/tick every day at 14:00 UTC. The route accepts the call only when the Bearer token equals CRON_SECRET.

Optional: deploy from the terminal

Use this when you want the same path as GitHub Actions. Production still requires a clean main matching origin/main.

  1. Create a token at https://vercel.com/account/tokens. That is VERCEL_TOKEN.
  2. From the repo: npx vercel link.
  3. Open .vercel/project.json. Copy orgId to VERCEL_ORG_ID and projectId to VERCEL_PROJECT_ID.
  4. Export those three values in the shell. Do not uncomment them inside .env.local.
  5. Preview, from any branch, does not migrate the database unless you pass --migrate:
bash scripts/deploy.sh preview
  1. Production, from updated main:
bash scripts/deploy.sh production

Optional: GitHub Actions

Repo Settings, Secrets and variables, Actions. Add VERCEL_TOKEN, VERCEL_ORG_ID, VERCEL_PROJECT_ID, and either SUPABASE_DB_URL or the three Supabase deploy secrets. .github/workflows/deploy.yml then migrates and runs vercel deploy --prebuilt --prod when a pull request is merged to main. From a repo admin account, bash scripts/protect-main.sh requires the check status before a merge.
